# 風格提案（T12-2a）

PRD 6.1（v2.3）老闆要求：現在的介面沒有自己的風格，先出 3 個明顯不同的風格方向，老闆選定後再寫進正式的 `DESIGN.md` 並全面套用（T12-2b）。

三個提案都是**同一個情境**：查詢商家「全聯」、查詢範圍「全部卡別」、金額 1000 元。推薦清單的內容（10 張卡的卡名、銀行、回饋率、上限、推薦理由、條件標籤、預估回饋金額、官方來源連結、檢核日期）完全相同，取自 `preview/` 的真實資料——實際跑過一次 `src/engine/recommend()`（`query:"全聯", cardIds:null, amount:1000, today:"2026-10-14"`），把輸出寫死在 `data.mjs`，三個頁面各自用 `createElement`/`textContent` 把它畫出來，只有樣式和排版不同。這樣老闆看三個提案時比較的是「風格」，不是「內容剛好不一樣」。

欄位文案維持跟正式頁面 `src/ui/app.mjs` 一致的寫法（例如「預估回饋約 23 元」「檢核日期：2026-10-10」），方便之後 T12-2b 直接沿用。

在 `products/cardpick/` 下啟動本機伺服器（例如 `PORT=8122 node scripts/server.mjs`），開：

## 提案 A：存摺手帳

**品牌色**：靛藍 `#1c2541`（標題、文字、數字、框線）
**輔助色**：磚紅 `#b33a3a`（「本期最高」徽章、第 1 名回饋率的唯一跳色）
**字體**：標題與數字用襯線字 `"Noto Serif TC", Georgia, serif`，內文用無襯線 `"Noto Sans TC", system-ui`——襯線數字模仿存摺上印刷的金額字，無襯線內文維持好讀。

**第 1 名的呈現**：整塊面板模仿存摺頁首，上下各一條細線像存摺的格線；右上角一個磚紅色、微微旋轉的「本期最高」印章式徽章；回饋率用超大襯線數字（3rem），整頁唯一的跳色就用在這裡，一眼能找到。

**名次列表的呈現**：仿照存摺明細列，序號用兩位數（01、02…），列與列之間用細虛線分隔（像帳本的分項線），回饋率靠右對齊、用 tabular 數字，跟存摺「金額靠右」的閱讀習慣一致。

**為什麼適合「刷哪張」**：使用者查完就是要「記一筆帳」——這張卡刷下去，回饋多少、上限多少。存摺頁首／明細列的隱喻讓「第 1 名」自然變成「這一頁最重要的一筆」，不需要額外的裝飾語彙；磚紅只用在最高回饋一處，避免花俏。缺點是襯線數字在手機小字級下稍微沒有無襯線銳利，但 1rem 以上的回饋率數字不受影響。

## 提案 B：扣款看板

**品牌色**：琥珀 `#f0b429`（唯一強調色：徽章、回饋率、按鈕、連結）
**輔助色**：冷灰藍 `#9aa3b2` / `#343a45`（次要文字、邊框、未強調的底色）
**字體**：標題用系統無襯線粗體；**回饋率、序號、檢核日期這些數字用等寬字** `"SF Mono", Consolas, Menlo, monospace`，模擬機場航班看板／提款機螢幕的數字排版（等寬字只用在真正的數字欄位，不是整頁內文，不違反「不用等寬字當內文」的通則）。

**第 1 名的呈現**：深色底，整塊面板用琥珀色 2px 框線框起來，像看板上被圈出來的那一格；左上角「No.1」實心琥珀徽章；回饋率是全頁最大的等寬數字，靠左，上限靠右對齊，像看板一行「目的地／時刻」的排法。

**名次列表的呈現**：深色清單，奇偶列用一階色階（`--panel` / `--panel-2`）區分，不用陰影或分隔線，數字一律等寬、靠右對齊，閱讀起來像看一排航班或扣款紀錄。

**為什麼適合「刷哪張」**：這個方向把「查詢」重新框成「即時結果顯示」——像結帳前瞄一眼看板，琥珀色只出現在真正重要的數字上，深色底在店內或車廂光線下也好辨識、不刺眼。三個提案中風格最「工具感」，最貼近「結帳前看一眼」的使用情境，但也是三者中最大膽的一個，需要老闆確認深色主題是否符合產品調性（目前正式頁面是全淺色）。

## 提案 C：卡面實感

**品牌色**：珊瑚橘 `#e8542f`（第 1 名卡面、強調按鈕）
**輔助色**：深墨綠 `#16433d`（卡面上的裝飾色塊、條件標籤、次要連結）
**字體**：標題用加粗無襯線 `"Arial Black", "Helvetica Neue", "Noto Sans TC"`，內文沿用系統無襯線；回饋率、金額加 tabular-nums。

**第 1 名的呈現**：做成一張真正的「信用卡比例」色塊（1.586:1，跟信用卡實體比例一樣），珊瑚橘實色填滿（無漸層），右上角一塊墨綠色的幾何色塊當裝飾（純色、不做漸層或光暈）；卡面上只留「本次最推薦」徽章、超大回饋率、銀行名＋卡名（像卡面上壓印的字），其餘資訊（上限、推薦理由、條件、官方來源）放在卡面下方，避免塞爆卡面版型。

**名次列表的呈現**：每一列左側一條墨綠色粗邊框（像卡片的側邊），银行+卡名在上、回饋率在右上角用品牌色標示，其餘資訊同樣收在下方一行灰字。

**為什麼適合「刷哪張」**：這個產品的核心動作就是「選一張實體卡刷下去」，把第 1 名畫成卡片形狀，直接把「選卡」的隱喻放進畫面——老闆在後續版本要加卡面圖（`DESIGN.md`「卡面圖」一節），這個方向跟卡面圖的目標最一致，色塊色卡可以之後直接換成真的卡面圖。三者中最活潑、最有記憶點，但也最需要注意別讓裝飾色塊喧賓奪主（已把色塊限制在卡面右上角一小塊，不覆蓋文字）。

## 共同遵守的規則（三個提案都一樣）

- 無障礙：表單欄位都有 `label`；`fieldset`/`legend` 包查詢範圍；`:focus-visible` 看得到焦點框；官方來源連結 `target="_blank" rel="noopener"`；裝飾用的色塊有 `aria-hidden="true"`。
- 手機：375px 寬無橫向捲動（已用 playwright-cli 檢查 `scrollWidth === clientWidth`）；按鈕都有 `touch-action: manipulation`、最小高度 44px；沒有 `user-scalable=no`。
- 數字：回饋率與金額都用 `font-variant-numeric: tabular-nums`。
- 深色模式（提案 B）：`<html style="color-scheme: dark">` 與 `<meta name="theme-color">` 對齊背景色。
- 不做 AI 味：無漸層、無發光按鈕、無霧面玻璃、無 emoji、無假的「New/Beta」徽章、無三張一樣的圖示卡片；文案用具體動作（「查詢」而不是「開始使用」）。
- 顯示資料一律用 `createElement`/`textContent`（`data.mjs` 寫死資料，三頁各自用小段 `<script type="module">` 渲染，不用 `innerHTML`）。
- 不載入網路字型：三個提案都只用系統字型堆疊（不同的字體堆疊本身就足以做出三種不同觀感），維持「結帳前打開要快」的原則，跟正式頁面 `DESIGN.md` 第 3 節的政策一致。

## 修正記錄

交件前用 playwright-cli 實際截圖時發現並修掉以下問題（不是「必改」清單，是這次自查抓到的 bug）：
1. 三個提案的第 1 名卡片最初把「推薦理由」渲染了兩次（卡片上方一次、`recMeta()` 裡又一次）；改成 `recMeta(rec, { includeReason: false })` 只渲染一次。
2. 名次列表最初把「回饋率＋上限」寫成同一段不換行的文字（`white-space: nowrap`），上限字數較長時（例如「每期帳單上限 15,000 點」）會把左邊的銀行名稱欄位擠到只剩一兩個字寬，中文字變成一個字一行；改成回饋率單獨一欄、上限移到下方可換行的說明行（`recMeta(rec, { includeCap: true })`）。
3. 提案 C 的第 1 名卡面原本把「銀行＋卡名＋方案」整段文字放進固定比例（1.586:1）的卡面裡，文字太長時超出卡面高度、被 `overflow: hidden` 裁掉；改成卡面上只放銀行名＋卡名（像卡面壓印字），完整的「銀行＋卡名＋方案」移到卡面下方當標題。
